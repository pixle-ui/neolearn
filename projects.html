TRYHACKME · 3 LABS

Web Application Security

Service exposure, web attack surfaces, and access-control testing.

Tomghost · Tomcat / AJP

Chaining Ghostcat with Credential Recovery

Objective: Assess the lab's Tomcat service, establish an initial foothold, and identify a path to root.

Methodology & Key Takeaways
  • Reconnaissance: Used Nmap to map exposed services and identify the Tomcat/AJP attack surface.
  • Exploitation: Validated the Ghostcat (CVE-2020-1938) file-read exposure in the authorized lab and used disclosed credentials for SSH access.
  • Credential recovery: Cracked a PGP key passphrase to decrypt a credential file and move laterally to a second user.
  • Privilege escalation: Abused an unsafe sudo permission for zip, applying the relevant GTFOBins technique to validate root-level impact.

Tools: Nmap, Metasploit Framework, John the Ripper (gpg2john), GnuPG, SSH, GTFOBins.

Vulnversity · File uploads

Upload Validation and SUID Escalation

Objective: Evaluate a web application's upload controls and determine whether local privilege boundaries can be bypassed.

Methodology & Key Takeaways
  • Reconnaissance: Used Nmap to identify exposed services and Gobuster to discover web application paths.
  • Exploitation: Assessed extension-based upload filtering and demonstrated why superficial file-name checks are insufficient.
  • Initial access: In the isolated lab, used an accepted server-side script extension to obtain a remote shell and confirm the access level.
  • Privilege escalation: Audited SUID programs, identified systemctl as an escalation path, and used the relevant GTFOBins technique to validate root-level impact.

Tools: Nmap, Gobuster, Netcat, GTFOBins.

Corridor · Access control

Identifying Predictable Object References

Objective: Assess whether predictable URL identifiers expose web resources that are not linked through the normal interface.

Methodology & Key Takeaways
  • Reconnaissance: Inspected application navigation and URL patterns, noting the consistent format of resource identifiers.
  • Enumeration: Determined that the identifiers were MD5 hashes of sequential numeric values.
  • Access-control testing: Manipulated an identifier to test for an insecure direct object reference (IDOR) and access to an unlinked lab resource.
  • Key takeaway: Confirmed that opaque or hashed identifiers do not replace server-side authorization checks.

Tools: Browser developer tools, MD5 hashing.

Network Enumeration & Linux Access

Service enumeration, credential security, initial access, and privilege escalation.

Basic Pentesting · Enumeration

From Service Enumeration to Credentialed Access

Objective: Assess exposed services and determine how weak credentials and SSH key protection could lead to account access.

Methodology & Key Takeaways
  • Reconnaissance and enumeration: Used Nmap and enum4linux to map services and identify SMB user information.
  • Web assessment: Enumerated web paths with Gobuster and reviewed discovered content for clues about weak credential practices.
  • Initial access: In the lab, tested SSH credential strength with Hydra and examined a private key associated with another user.
  • Credential recovery: Cracked the SSH key passphrase with John the Ripper and used the recovered access to complete the lab objectives.

Tools: Nmap, Gobuster, enum4linux, Hydra, John the Ripper (ssh2john), SSH.

Wgel CTF · Linux privilege escalation

Source Review and Sudo Misconfiguration

Objective: Combine web reconnaissance with host permission analysis to reach the lab's privileged objective.

Methodology & Key Takeaways
  • Reconnaissance: Scanned services with Nmap and inspected HTML source for user-identifying information.
  • Web enumeration: Used Gobuster to locate an exposed SSH-related directory and assess the risk of publishing private authentication material.
  • Initial access: Retrieved the lab's exposed RSA key and used it to authenticate over SSH.
  • Privilege escalation: Identified unrestricted sudo use of wget and demonstrated its impact against protected lab data.

Tools: Nmap, Gobuster, wget, Netcat, SSH.

Bounty Hacker · FTP / sudo

Anonymous FTP and Excessive Tar Privileges

Objective: Assess anonymous FTP exposure and determine how weak SSH credentials and broad sudo permissions affect host security.

Methodology & Key Takeaways
  • Reconnaissance: Used Nmap to identify FTP and SSH services and verified anonymous access to the lab FTP server.
  • Exposure assessment: Reviewed accessible task materials and evaluated the risks of distributing account and password-related information.
  • Initial access: Evaluated SSH credential strength in the authorized environment with Hydra to obtain a lab account.
  • Privilege escalation: Identified excessive sudo permission for tar and applied the corresponding GTFOBins technique to validate root-level impact.

Tools: Nmap, FTP, Hydra, SSH, GTFOBins.
